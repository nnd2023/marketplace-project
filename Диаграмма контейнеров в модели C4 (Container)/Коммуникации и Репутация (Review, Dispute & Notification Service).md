# Контейнер: Коммуникации и Репутация (Review & Dispute API + Reputation DB + Notification Worker + Notif DB)
## Зачем нужен: 
Управление отзывами и рейтингами товаров/продавцов, обработка споров, а также централизованная отправка уведомлений (SMS, Email, Push) по событиям системы. Обеспечивает рендеринг шаблонов, маршрутизацию по каналам и историю отправок.

## Входные данные (Reputation):

- Отзыв (текст, оценка, ID товара/заказа)
- Запрос на модерацию отзыва (администратор)
- Данные для открытия спора (покупатель/продавец)
- Статусы разрешения споров

## Входные данные (Notification):

- События из Message Broker (OrderCreated, PaymentCompleted, ReviewSubmitted, etc.)
- Шаблоны уведомлений (конфигурация от администратора)
- Запросы на отправку конкретного уведомления (например, сброс пароля)

## Выходные данные (Reputation):

- Средний рейтинг товара/продавца
- Список отзывов с пагинацией
- Статус спора (решён, отклонён)
- Событие ReviewSubmitted (публикуется в Broker для обновления рейтингов)

## Выходные данные (Notification):

- Доставленное уведомление через внешние шлюзы (SMS, Email, Push)
- Лог отправки в NotifDB (история)
- Статус доставки (успех/ошибка)

## Интеграции:

- Чтение/запись в ReputationDB (PostgreSQL) — схемы Review, Dispute
- Чтение/запись в NotifDB (PostgreSQL) — схема Notification, история
- Публикация ReviewSubmitted в Message Broker (для обновления рейтингов в CatalogAPI)
- Потребление событий из Message Broker (OrderCreated и др.) для генерации уведомлений
- Внешний NotificationSvc (SMS/Email/Push-шлюзы) — фактическая отправка
- API Gateway forward запросов на получение/создание отзывов

## Нефункциональные требования:

- Время отклика для получения отзывов < 200 мс
- Асинхронная отправка уведомлений (не блокирует основной поток)
- Гарантия доставки уведомлений (retry с экспоненциальной задержкой)
- Поддержка различных языков для шаблонов
- Масштабирование Notification Worker для обработки больших объёмов (пиковые рассылки)
- Аудит истории уведомлений (для решения спорных ситуаций)
