# Контейнер: Заказ и Логистика (Order API + Orders DB + Logistics Worker)
## Зачем нужен: 
Управление корзиной, оформлением заказов, статусной моделью (DRAFT → PAID → SHIPPED → DELIVERED), а также синхронизация с внешней службой доставки для отслеживания трекинг-номеров и статусов отправлений.

## Входные данные:

- user_id (покупатель)
- Список товаров (product_id + quantity)
- Адрес доставки, способ доставки
- Idempotency-ключ для защиты от дублей
- Статусы обновления от Logistics Worker (трекинг-номер, статус отправления)

## Выходные данные: 

- order_id (номер заказа)
- Текущий статус заказа
- Информация о корзине (состав, сумма)
- Трекинг-номер для отслеживания
- События: OrderCreated, PaymentPending (публикуются в Message Broker)

## Интеграции:

- Вызов FinanceAPI для инициирования оплаты (синхронно или через Gateway)
- Чтение/запись в OrdersDB (PostgreSQL) — схемы Order, OrderItem, Shipment
- Публикация событий в Message Broker (OrderCreated, PaymentPending)
- LogisticsWorker потребляет события для получения трекинг-номеров через внешний LogisticsAPI и обновляет OrdersDB
- API Gateway forward запросов

## Нефункциональные требования:

- Время ответа на создание заказа < 2 сек (включая проверку товаров и расчёт стоимости)
- Идемпотентность по idempotency_key
- Гарантированная доставка события OrderCreated (даже при сбоях)
- Поддержка rollback при неудачной оплате (компенсирующие транзакции)
- Масштабирование для пиковых нагрузок (распродажи)
- Чтение корзины с кешированием (Redis)
