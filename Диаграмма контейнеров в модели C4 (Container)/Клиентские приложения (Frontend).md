# Контейнер: Клиентские приложения (Frontend)
## Зачем нужен: 
Предоставление пользовательских интерфейсов для разных ролей: покупатели (веб и мобильное приложение), продавцы (портал) и персонал (админ-панель). Обеспечивают визуализацию каталога, корзины, оформления заказа, личного кабинета, управления товарами, финансами, модерации и логистики.

## Входные данные:
- Действия пользователя (клики, ввод текста, загрузка файлов)
- Данные форм (поисковые запросы, параметры фильтрации, данные корзины, адрес доставки, способы оплаты, отзывы, настройки товаров)
- JWT-токен аутентификации (из API Gateway после входа)
- Медиафайлы (изображения товаров, документы)

## Выходные данные:
- Отображённые страницы с данными (каталог, детали товара, корзина, история заказов, статусы, отзывы, отчёты)
- Запросы к API Gateway (REST/GraphQL) для выполнения бизнес-операций
- Presigned URL для загрузки изображений в CDN
- Push-уведомления (получаемые через Notification Service)

## Интеграции:
- Все запросы проходят через API Gateway (маршрутизация, аутентификация, rate-limiting)
- Клиентские приложения напрямую не интегрируются с внутренними сервисами, только через Gateway
- Мобильное приложение дополнительно интегрируется с сервисом push-уведомлений (через NotificationSvc внешний)

## Нефункциональные требования:
- Время загрузки страницы < 2 сек (при 95-м перцентиле)
- Адаптивность и кроссбраузерность (веб)
- Офлайн-режим для базовых операций (мобильное приложение)
- Поддержка до 10 000 одновременных пользователей
- Безопасное хранение токенов (HttpOnly, Secure)
- Локализация (несколько языков, валют)
- Версионирование API для обратной совместимости
