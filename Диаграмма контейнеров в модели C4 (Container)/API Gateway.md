# Контейнер: API Gateway
## Зачем нужен: 
Единая точка входа для всех клиентских запросов. Выполняет маршрутизацию к соответствующим микросервисам, JWT-аутентификацию, ограничение частоты запросов (rate-limiting), терминирование SSL, агрегацию логов и мониторинг.

## Входные данные:

- HTTP-запросы от клиентских приложений (REST/GraphQL) с JWT-токеном в заголовке
- Путь запроса, HTTP-метод, тело запроса (JSON), параметры
- Idempotency-ключи для идемпотентных операций

## Выходные данные:

- Перенаправленные запросы к внутренним API (AuthAPI, CatalogAPI, OrderAPI, FinanceAPI, ReputationAPI, NotificationWorker)
- Ответы от внутренних сервисов, возвращаемые клиенту с соответствующими HTTP-статусами
- Ошибки аутентификации/авторизации (401/403), ошибки rate-limiting (429)

## Интеграции:

- Forward запросов к AuthAPI, CatalogAPI, OrderAPI, FinanceAPI, ReputationAPI, NotificationWorker
- Проверка JWT (возможно, интеграция с AuthAPI для валидации или локальная проверка)
- Интеграция с системой мониторинга (Prometheus, ELK) для сбора метрик

## Нефункциональные требования:

- Задержка маршрутизации < 50 мс (средняя)
- Пропускная способность > 10 000 RPS
- Горизонтальное масштабирование (Kong/Nginx в кластере)
- Надёжность: автоматическое переключение при сбоях сервисов (retry/circuit breaker)
- Поддержка WebSocket (если требуется для уведомлений в реальном времени)
- Централизованное логирование всех запросов
