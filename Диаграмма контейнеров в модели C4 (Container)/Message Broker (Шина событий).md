# Контейнер: Message Broker (RabbitMQ/Kafka)
## Зачем нужен: 
Асинхронная шина событий для слабой связанности микросервисов. Обеспечивает надёжную доставку событий, таких как создание заказа, завершение платежа, отправка уведомлений и обновление трекинга. Позволяет сервисам обмениваться данными без блокирующих вызовов.

## Входные данные (публикуемые события, пример):

- OrderCreated, PaymentPending от OrderAPI
- PaymentCompleted, PayoutScheduled от FinanceAPI
- ReviewSubmitted от ReputationAPI
(другие события: ShipmentUpdated, UserRegistered, etc.)

## Выходные данные (потребляемые события, доставляются подписчикам):

- NotificationWorker потребляет события для отправки уведомлений (SMS/Email/Push)
- LogisticsWorker потребляет события для синхронизации трекинг-номеров и статусов
- CatalogAPI может потреблять события об изменении заказов для аналитики

## Интеграции:

- OrderAPI → публикует в очередь/топик
- FinanceAPI → публикует
- ReputationAPI → публикует
- NotificationWorker → потребляет
- LogisticsWorker → потребляет

- (возможно) другие сервисы-подписчики (например, для обновления поискового индекса)

## Нефункциональные требования:

- Гарантированная доставка сообщений (at-least-once)
- Задержка доставки < 100 мс (P95)
- Поддержка репликации для высокой доступности
- Возможность обработки пиковых нагрузок (буферизация)
- Мониторинг глубины очередей и задержек
- Поддержка разделения на топики/очереди по бизнес-доменам для изоляции
